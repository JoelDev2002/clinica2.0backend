Rúbrica Evaluación parcial
Logros esperados ● Emplea los fundamentos de C# en el desarrollo de aplicaciones con .NET Core, garantizando una sintaxis clara y fuertemente 
tipada para mejorar la mantenibilidad y legibilidad del código.
● Aplica las buenas prácticas del estilo de arquitectura REST y los principios del diseño de microservicios para la creación de
proyectos escalables y mantenibles.
Indicaciones:
● Contexto o situación problemática: 
Una clínica privada necesita gestionar las citas médicas que los pacientes solicitan a diario. Actualmente, las citas se anotan manualmente en agendas físicas o se 
confirman por llamadas telefónicas sin un control unificado, lo que genera confusión, pérdida de información y sobrecarga para el personal administrativo.
Para solucionar este problema, como parte del equipo de desarrollo backend, usted y dos integrantes más han sido asignados para construir una API RESTful con C# 
y .Net Core, con el objetivo de registrar, consultar, actualizar y cancelar citas médicas de manera eficiente y ordenada.
● Pasos: 
1. Modelado de clases
○ Crear clases como Cita, Paciente, Médico, según el alcance definido.
○ Simular el almacenamiento de datos usando listas o mapas (List<Cita>).
2. Estructura del proyecto
○ Separar el proyecto en paquetes: controller, service, model.
Escuela de Tecnología
○ Usar interfaces y clases de servicio para manejar la lógica de negocio.
3. Creación de API REST
○ Implementar endpoints CRUD (GET, POST, PUT, DELETE).
○ Validar datos de entrada usando anotaciones como [Required], [StringLength], etc.
4. Manejo de errores
○ Implementar un manejo de excepciones centralizado.
5. Documentación y pruebas
○ Documentar endpoints y realizar pruebas funcionales con Postman.
● Producto:
Aplicación desarrollada con .Net Core que cumpla con:
○ Registrar, consultar, actualizar y eliminar citas médicas de manera eficiente.
○ Gestionar la información en estructuras de datos en memoria (ej. List, Map).
○ Aplicar buenas prácticas de arquitectura de capas (controladores, servicios, modelos).
○ Garantizar una sintaxis clara y tipada en C#.
○ Documentar adecuadamente los endpoints de la API.
○ Incluir validaciones con anotaciones y pruebas funcionales con Postman.
○ Simular el manejo de datos sin conexión a base de datos, utilizando listas en memoria o colecciones para almacenar temporalmente la información durante 
la ejecución.
La aplicación deberá ser subida a un repositorio en GitHub o plataforma similar, conteniendo el código fuente con una estructura clara y organizada, además de un 
archivo README.md con instrucciones para instalar y ejecutar la aplicación. Adicionalmente, se solicitará un informe técnico que incluya la descripción del proyecto, 
las capturas de las pruebas realizadas con Postman, el enlace del repositorio en GitHub o plataforma similar (con permisos de acceso de lectura para el docente), así 
como la explicación de la estructura general del código y los roles del equipo en el desarrollo del proyecto.
● Modalidad de trabajo: Grupal (3 integrantes). Los grupos deben formarse a más tardar en la sesión en la que se explica la rúbrica.
● Parámetros de formato de presentación: Informe técnico en versión PDF.
Solo 1 integrante del equipo debe subir el entregable a la plataforma virtual, ya que la calificación será común a todos los integrantes.
